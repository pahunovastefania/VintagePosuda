## 1. Введение

Современная разработка веб-приложений невозможна без понимания
кроссплатформенных сред исполнения. Платформа .NET начиная с версии 5
является кроссплатформенной по умолчанию — одна и та же сборка работает
на Windows, Linux и macOS, а инструменты CLI и контейнеризация позволяют
переносить приложение между средами без изменения кода.

В рамках курсового проекта разработано веб-приложение для управления
каталогом магазина винтажной посуды. Проект демонстрирует ключевые
возможности .NET 8: ASP.NET Core, Blazor Server, Entity Framework Core
с подходом Code First, миграции БД, Dependency Injection, валидация,
аутентификация, контейнеризация через Docker, юнит-тестирование.

## 2. Постановка задачи

Согласно требованиям ТЗ необходимо реализовать веб-приложение, которое:

- решает практическую задачу — каталогизация предметов в магазине
  винтажной посуды;
- использует Entity Framework Core с подходом Code First и миграциями;
- хранит данные в SQLite;
- имеет веб-интерфейс на Blazor (Server) с Razor-компонентами и роутингом;
- содержит все три типа отношений между сущностями: 1:1, 1:N и N:N;
- использует репозиторный паттерн и Dependency Injection через
  `IServiceCollection`;
- имеет валидацию форм через FluentValidation;
- полностью контейнеризируется (Dockerfile + docker-compose.yml);
- покрыт юнит-тестами с coverage > 70 % по бизнес-логике;
- размещается в Git-репозитории с ветками `main`, `dev`, `feature/*`.

Базовые операции, которые должно выполнять приложение:
1. Добавление нового предмета.
2. Редактирование карточки.
3. Удаление и архивация (продано).
4. Поиск по названию, заводу, году.
5. Простые отчёты «Что в наличии» и «Что продано».

## 3. Обзор технологий

### .NET 8 и ASP.NET Core 8

Платформа .NET 8 — современная кроссплатформенная среда выполнения с
JIT-компилятором, оптимизированным сборщиком мусора и большой стандартной
библиотекой. ASP.NET Core 8 — веб-фреймворк для построения серверных
приложений: Razor Pages, MVC, Web API и Blazor.

### Blazor Server

Blazor Server — модель работы Blazor, при которой UI-логика выполняется
на сервере, а в браузере отображается результат рендеринга через
WebSocket-соединение (SignalR). Преимущества:
- быстрый старт страницы — не нужно скачивать .NET-рантайм в браузер;
- полный доступ к серверным сервисам через DI;
- меньший размер бандла по сравнению с WebAssembly.

В .NET 8 шаблон называется **Blazor Web App** и поддерживает разные режимы
интерактивности; для данного проекта выбран режим `InteractiveServer`.

### Entity Framework Core 8

EF Core — современная ORM от Microsoft. Подход Code First означает, что
сущности описываются в коде (классы C#), а схема БД генерируется
автоматически через миграции. В проекте используются:
- классы сущностей (`Item`, `Manufacturer`, `Category` и др.);
- `DbContext` (`ApplicationDbContext`) с `DbSet<T>`;
- конфигурации через Fluent API (`IEntityTypeConfiguration<T>`);
- автогенерируемые миграции (`dotnet ef migrations add …`);
- автоматическое применение миграций при старте приложения
  (`db.Database.MigrateAsync()`).

### SQLite

SQLite — файловая встраиваемая СУБД. Идеальна для учебного проекта:
не требует отдельного процесса, работает на всех ОС, поддерживается
EF Core «из коробки». Для тестов используется SQLite in-memory
(`DataSource=:memory:`).

### Docker и multi-stage build

Docker позволяет упаковать приложение и все его зависимости в один образ,
работающий одинаково на любой Linux-совместимой системе. Multi-stage build
снижает размер итогового образа: первая стадия (`sdk:8.0`) восстанавливает
пакеты и собирает приложение, вторая стадия (`aspnet:8.0`) включает только
runtime и опубликованные файлы.

### FluentValidation

Библиотека для декларативной валидации объектов. По сравнению с
DataAnnotations предоставляет более выразительный fluent-синтаксис,
условия (`When`), коллекции правил, переиспользование через наследование.

## 4. Архитектура приложения

Приложение построено по слоистой архитектуре:

```
┌─────────────────────────────────────────────────────┐
│  UI: Razor Components + Razor Pages (Login/Register)│
├─────────────────────────────────────────────────────┤
│  Validators (FluentValidation)                      │
├─────────────────────────────────────────────────────┤
│  Services: IItemService, IReportService, ...        │
├─────────────────────────────────────────────────────┤
│  Repositories: IRepository<T>, IItemRepository      │
├─────────────────────────────────────────────────────┤
│  EF Core: ApplicationDbContext + Configurations     │
├─────────────────────────────────────────────────────┤
│  SQLite (app.db)                                    │
└─────────────────────────────────────────────────────┘
```

### Dependency Injection

Все сервисы и репозитории регистрируются в `IServiceCollection`.
Регистрация вынесена в extension-метод `AddApplicationServices`
(`Extensions/ServiceCollectionExtensions.cs`):

```csharp
public static IServiceCollection AddApplicationServices(this IServiceCollection services)
{
    services.AddScoped(typeof(IRepository<>), typeof(Repository<>));
    services.AddScoped<IItemRepository, ItemRepository>();
    services.AddScoped<IItemService, ItemService>();
    services.AddScoped<IManufacturerService, ManufacturerService>();
    // ...
    return services;
}
```

В `Program.cs` это вызывается одной строкой:
```csharp
builder.Services.AddApplicationServices();
```

### Слой сервисов

Каждый сервис описывается интерфейсом и реализацией. Это позволяет
- легко мокать зависимости в тестах;
- заменять реализацию (например, добавить кэширование) без правки UI.

`IItemService` — главный сервис каталога. Содержит методы
`SearchAsync`, `GetByIdAsync`, `CreateAsync`, `UpdateAsync`,
`MarkAsSoldAsync`, `ArchiveAsync`, `RestoreAsync`, `DeleteAsync`.

### Слой репозиториев

`IRepository<T>` — обобщённый CRUD-интерфейс. `IItemRepository`
расширяет его специфичными методами (`SearchAsync`, `GetWithDetailsAsync`,
`SetTagsAsync`).

## 5. Модель данных

### ER-диаграмма (Mermaid)

```mermaid
erDiagram
    Item ||--o| ItemDetails : "1↔1"
    Item ||--o{ ItemPhoto : "1→N"
    Item }|--|| Manufacturer : "N→1"
    Item }|--|| Category : "N→1"
    Item }|--|| Material : "N→1"
    Item ||--o{ ItemTag : "N↔N"
    Tag  ||--o{ ItemTag : "N↔N"

    Item {
        int Id PK
        string Name
        int Year
        decimal Price
        ItemStatus Status
        DateTime CreatedAt
        DateTime SoldAt
        int ManufacturerId FK
        int CategoryId FK
        int MaterialId FK
    }
    ItemDetails {
        int ItemId PK_FK
        string Origin
        string Provenance
        string Condition
        string Defects
    }
    ItemPhoto {
        int Id PK
        int ItemId FK
        string Url
        bool IsPrimary
    }
    Manufacturer {
        int Id PK
        string Name
        string Country
        int FoundedYear
        int ClosedYear
    }
    Category {
        int Id PK
        string Name
    }
    Material {
        int Id PK
        string Name
    }
    Tag {
        int Id PK
        string Name
    }
    ItemTag {
        int ItemId PK_FK
        int TagId PK_FK
    }
```

### Все три типа отношений (требование ТЗ)

| Тип | Где |
| --- | --- |
| **1:1** | `Item` ↔ `ItemDetails`. PK у `ItemDetails` совпадает с FK на `Item`. |
| **1:N** | `Manufacturer → Items`, `Category → Items`, `Material → Items`, `Item → ItemPhotos`. |
| **N:N** | `Item ↔ Tag` через явную сущность-связку `ItemTag` с составным ключом `(ItemId, TagId)`. |

Все конфигурации описаны через **Fluent API** в каталоге
`Data/Configurations/`. Регистрация всех конфигураций в `OnModelCreating`
выполняется одной строкой:

```csharp
modelBuilder.ApplyConfigurationsFromAssembly(typeof(ApplicationDbContext).Assembly);
```

### Миграции

Стартовая миграция называется `InitialCreate`:

```bash
dotnet ef migrations add InitialCreate --project src/VintagePosuda.Web --output-dir Data/Migrations
```

Файлы миграции хранятся в `Data/Migrations/` и закоммичены в репозиторий.
При первом запуске приложения миграции применяются автоматически
(`db.Database.MigrateAsync()` в `Program.cs`).

## 6. Описание реализации основных операций

### Добавление нового предмета

Маршрут `/items/new` ведёт на компонент `Components/Pages/ItemForm.razor`.
Форма построена на `EditForm` + `FluentValidationValidator`. После
нажатия «Создать» вызывается `IItemService.CreateAsync(item, tagIds)`,
который добавляет предмет в БД, проставляет `CreatedAt` и связки `ItemTag`.

### Редактирование карточки

Тот же `ItemForm.razor`, но с маршрутом `/items/{id}/edit`. Форма
загружает существующий предмет через `Items.GetByIdAsync(id)`, сохраняет
изменения через `Items.UpdateAsync(model, tagIds)`. `UpdateAsync`
обновляет только редактируемые поля и не трогает `CreatedAt`.

### Удаление и архивация

На странице карточки (`ItemDetailsPage.razor`) кнопки:
- **Отметить проданным** — открывает модалку с выбором даты, вызывает
  `MarkAsSoldAsync(id, soldAt)`. Статус становится `Sold`, `SoldAt`
  заполняется выбранной датой.
- **Архивировать** — модалка подтверждения, затем `ArchiveAsync(id)`.
- **Удалить** (только для роли `Admin`, через `<AuthorizeView Roles="Admin">`)
  — модалка подтверждения, затем `DeleteAsync(id)` с физическим удалением
  (каскад на `ItemDetails`, `ItemPhotos`, `ItemTags`).

### Поиск

На главной странице (`Catalog.razor`) форма с полями:
- название (LIKE %name%);
- завод (LIKE %manufacturer%);
- год (точное совпадение);
- статус (выпадающий список).

Параметры собираются в DTO `SearchQuery` и передаются в
`IItemService.SearchAsync`. Реализация в `ItemRepository.SearchAsync`
строит IQueryable c `EF.Functions.Like` и `Include` для подгрузки
связанных сущностей.

### Отчёты

Маршрут `/reports`. Компонент `Reports.razor` показывает две вкладки:
«В наличии» и «Продано». Каждая отрисовывает компонент `ReportTable`
с заголовком, столбцами и итогом по сумме (`StockReport.TotalPrice`).

## 7. Контейнеризация

Файл `src/VintagePosuda.Web/Dockerfile` использует **multi-stage build**:

1. **Stage `build`** на образе `mcr.microsoft.com/dotnet/sdk:8.0`:
   - кэширует `restore` через раздельное копирование `csproj`;
   - публикует в Release-конфигурации в `/app/publish`.
2. **Stage `runtime`** на образе `mcr.microsoft.com/dotnet/aspnet:8.0`:
   - устанавливает `curl` для HEALTHCHECK;
   - создаёт каталог `/app/data` под SQLite-базу с правами на запись для
     non-root пользователя `app`;
   - копирует опубликованные файлы;
   - запускает `dotnet VintagePosuda.Web.dll`.

Файл `docker-compose.yml`:
- собирает образ из контекста проекта;
- публикует порт 8080;
- монтирует named volume `app-data` в `/app/data`;
- через переменную окружения `ConnectionStrings__DefaultConnection`
  переопределяет строку подключения, чтобы база лежала в volume;
- описывает `HEALTHCHECK` (curl на `/health` каждые 30 секунд).

Запуск:

```bash
docker compose up --build
```

Healthcheck реализован через `Microsoft.Extensions.Diagnostics.HealthChecks`
плюс пакет `AspNetCore.HealthChecks.Sqlite`:

```csharp
builder.Services.AddHealthChecks()
    .AddSqlite(connectionString, name: "sqlite-db");
// ...
app.MapHealthChecks("/health");
```

Запрос `GET /health` возвращает `Healthy` если все проверки
прошли (БД доступна, схема создана).

## 9. Безопасность и аутентификация

### ASP.NET Core Identity

Используется `AddIdentity<ApplicationUser, IdentityRole>` с настройкой
требований к паролю. Хранилище — `EntityFrameworkStores`. Cookie-based
аутентификация (`ConfigureApplicationCookie`).

Страницы:
- `/Account/Login` (Razor Page);
- `/Account/Register` (Razor Page);
- `POST /Account/Logout` (minimal API endpoint в `Program.cs`).

### Роли

При первом запуске `DbInitializer` создаёт две роли:
- **Admin** — может удалять предметы физически и управлять справочниками;
- **Manager** — может добавлять и редактировать предметы.

Учётная запись первого администратора берётся из секции конфигурации
`AdminUser` и может быть переопределена переменными окружения.

Регистрирующиеся через `/Account/Register` пользователи автоматически
получают роль `Manager`.

### Авторизация в UI

В Blazor-компонентах используется `<AuthorizeView>` (для условного
рендеринга) и атрибут `[Authorize]` (для защиты страниц целиком).
Например, форма создания/редактирования предмета доступна только
аутентифицированным пользователям:

```razor
@page "/items/new"
@page "/items/{Id:int}/edit"
@attribute [Authorize]
```

Если гость попадает на `/items/new`, маршрутизатор отрабатывает
`<NotAuthorized>` и редиректит на `/Account/Login`.
